# Counting tours and matchings with monotone permanent oracles

A polynomial-size monotone arithmetic circuit using the permanent as an oracle cannot count Hamiltonian tours or general-graph perfect matchings exactly on all Boolean inputs. In the explicit circuit size model the lower bound is exponential in the number of target graph vertices. The proof allows arbitrarily many nested permanent gates, repeated input labels and reuse of intermediate values. The single-projection consequence gives a proposed answer to both parts of Grochow's 2017 Question 5.2. This research note has undergone independent internal checks. It has not received outside peer review, and priority has not been established. [Grochow’s original question](https://toc.cs.uchicago.edu/articles/v013a018/v013a018.pdf)

A Boolean input hides the difference between a variable and all its positive powers. Exact counting still reveals the *set* of labels in every monomial because its coefficient is positive. On a parse producing a perfect matching, for example, the labels incident to a fixed graph vertex must all name the same edge. A source perfect matching can contain many copies of that label. The tight-cut proof builds a common polynomial-size polytope that can recover all these choices. A 3 by 3 example in the paper explains why the ordinary assignment polytope alone can lose the needed information.

Read `corner-projection.md` for the single-oracle theorem and `corner-oracle-circuits.md` for shared circuits. The papers also give a sufficient subset of the Boolean tests and a directed-to-undirected tour reduction. The argument uses the published exponential extension-complexity bound for the perfect matching and traveling salesman polytopes. The corresponding Boolean decision problem allows larger positive supports and remains open in this oracle model. Classical Boolean P versus NP remains open. [Rothvoß’s lower bound](https://arxiv.org/abs/1311.2369)

The coefficient-preserving construction in `purification.md` and the `compiler/` directory provides a second way to use the result. On supports with exactly one distinct label per specified readout it converts a corner-counting circuit into an ordinary formal monotone circuit with the same oracle, at polynomial overhead. Its finite tests use exact integer and rational arithmetic.

The exact-dimension note identifies where extra affine coordinates are needed. Each full 3 by 3 terminal factor in a tight-cut decomposition contributes exactly one necessary dimension. All other factors use the original edge coordinates. This gives a simultaneous formulation with at most the number of physical edges plus six inequalities per exceptional factor.
