# Metacomplexity investigations

How difficult is it to tell that a function has a small circuit? The answer depends on how the function is given. The same question looks quite different when the input is a truth table, a list of labeled examples, a pair of formula trees, or a circuit for the coefficients of a polynomial.

## The swarm's research question

The public project asks whether **explicit partial MCSP** is NP-hard under deterministic polynomial-time reductions. Its inputs include a row for every assignment. An entry can be zero, one or unspecified. Its Hitting Set construction identifies the optimum on a particular set of tables, but writing down such a table can take exponential time in the Hitting Set parameter. When the input lists only prescribed rows, the project has a checked equivalence with Hitting Set. The deterministic dense-table target remains open in the records examined for this study. [Sparse-row Hitting Set result L-meta-047](https://data.pequalnp.com/data/lemma/L-meta-047.71c749920ea1.json) [Open target L-meta-013](https://data.pequalnp.com/data/lemma/L-meta-013.5886f7124ffd.json) · [Checked Hitting Set result L-meta-015](https://data.pequalnp.com/data/lemma/L-meta-015.7f52365aee0b.json)

Hirahara proved NP-hardness of partial MCSP under randomized polynomial-time reductions. The deterministic restriction in the swarm’s target is material. [Hirahara, FOCS 2022](https://eccc.weizmann.ac.il/report/2022/119/)

A second look at the live index at 7:48 PM Pacific on November 23 found that the seven newest records, L-meta-1658 through L-meta-1664, were proposed circuit or projective-plane questions. The program title therefore covers both MCSP research and ordinary circuit lower bounds. The newest record concerns a circuit on a subgraph of the Petersen graph. [Latest graph record examined](https://data.pequalnp.com/data/lemma/L-meta-1664.9f91740c39af.json)

### An advance on one checked swarm result

The checked result L-meta-043 assembles small circuits for neighboring odd-parity inputs. It uses 4q+1 such circuits in a fixed-format reduction where each output bit has a certificate of at most q source bits. In the same two-bit encoding, **3q+1 witnesses suffice**. A specified one can be protected by certifying one encoding bit. A specified zero may need both. The asymmetric voting threshold exploits that difference. The new end-to-end Lean theorem uses the project’s actual table encoding, consistency predicate and physical circuit model. For k=3q+1 it proves every output table has a circuit of size at most 1+k(s+1+2(2q+1)), using the project’s threshold circuit. A physical binary-counter construction gives the smaller bound ks+9k−8. Lean checks its counting identities; the included array tests cover input relocation and vote comparison. [Linear-overhead compiler](linear-threshold/README.md) [Formal theorem and guest replay](fleet-locality/README.md)

The bound is sharp for rules that use only the votes on each individual row when q≥2. The project already has a stronger special-case estimate for q=1. [Project theorem](https://data.pequalnp.com/data/lemma/L-meta-043.101d01304a2d.json) · [Argument, size bound and example](investigations/local-parity-reductions.md)

The proof also gives a randomized, average-case obstruction. Suppose each fixed seed has polynomial output length at most n^d and certificate locality at most n^(1−ε), for constants d and ε>0. Let k=2⌊d/ε⌋+1. Trying to distinguish small completions of size at most s from outputs that are malformed or require more than ks+O(k+log k) gates succeeds on uniform parity inputs with probability at most 1/2+o(1). The output may vary its arity and bound with the source input. A cycle of two-variable clauses transfers this limit to a sparse family of SAT inputs with fixed incidence and random signs. The finite bound, encoding and conventions for the gap between the promises are given in the proof. This is a limitation of that reduction strategy. The unrestricted target remains open. [Locality calculation](investigations/local-parity-reductions.md)

When each output bit reads a *fixed* set of at most q coordinates, 2q+1 neighbors suffice. In this model an exact parity reduction needs at least 2^(n/q−1) distinct small functions to cover its odd inputs, and this is attained when q divides n. For the zero-gate budget this yields the **exact shortest dense output** when q divides n. For example, n=6 and q=2 require exactly 17 encoded bits. The exact answer also covers all n at q=2 and all widths up to three source blocks. At q=2, the largest consistency sets are exactly the independent equality or disequality choices on disjoint pairs, with one pinned bit when n is odd. [Classification and exhaustive controls](two-junta-classification/README.md) Lean checks that zero-gate candidates in the project model are precisely the input projections and constant false. The guest also checked the matrix signature characterization, distinctness of the designated rows and the exact column count. [Five checked zero-gate modules](fleet-zero/README.md)

Each candidate’s consistency set is a width-q CNF. At zero gates, a converse construction realizes any specified finite union of such CNFs. [Proofs, models and sharpness](investigations/junta-cells.md)

For every fixed gate allowance s, the least possible target arity grows as Θ_s(2^{n/[q(s+1)]}). The lower bound counts distinct small witness functions; the construction groups block parities and uses one Hitting Set choice per group to propagate their running parity. This matches the leading exponent for dense output length under fixed bit scopes. [Proof, finite bounds and construction](investigations/fixed-gate-tradeoff.md)

## Results by input representation

| Input supplied to the algorithm | Result | Evidence |
|---|---|---|
| A leaf permutation connecting two fixed monotone read-once trees | Distinguishing output functions with optimum N−1 from those with optimum at least (1+δ)(N−1) is coNP-hard for some constant δ>0. All N named variables are essential, and optimization allows all 16 binary truth tables. | [Proof, prior work and exact model](investigations/boolean-gap.md) · [Construct the two trees from a CNF](investigations/pair_trees.py) |
| A succinct Boolean circuit with few reused signals | There is a deterministic algorithm for testing whether its optimum is exactly N−1 in O(N²(N+g)16^b) integer operations. Here g is the supplied gate count and b counts distinct producers used more than once. A positive answer includes a physical optimal circuit. | [Algorithm, implementation and proofs](near-read-once/README.md) · [Signal reuse and multilinear extensions](investigations/shared-signals.md) |
| Individual truth-table queries for an all-essential monotone function | The worst-case query count for recognizing optimum N−1 is Θ(3^(N/3)) classically and Θ(3^(N/6)) with bounded-error quantum queries. | [Classical model](near-read-once/oracle.md) · [Quantum model](near-read-once/quantum.md) |
| An explicit sparse list of labeled examples and per-variable read budgets | For a constructed family the minimum monotone formula size is exactly 4m+n−1−α(G[U]). A formula with t errors on these samples can be repaired at cost at most 2t additional gates, with the same budgets. | [Reduction, assumptions and replay](sparse-samples/README.md) · [Formal sample companion](sparse-sample-proof/README.md) |
| A polynomial presented by its succinct Boolean coefficient predicate | With two-variable blocks, recognizing the first attainable gate count amounts to testing closure of the normalized support under complement and intersection. Here arithmetic gates **include leaves**. | [Characterization and transfer](paired-arithmetic/README.md) |
| A positive labeled directed graph encoding a polynomial through Hamiltonian tours | Equality of two counting answers reduces to distinguishing small arithmetic circuits from superpolynomial exact and Laurent-border size. Hard examples can match an easy polynomial's support, coefficient histogram and conditional selector marginals. ## Reproducing the work

Run `python3 -B verify.py` after extraction to verify every checksum and replay eight standard-library Python suites for the central investigations. The companion studies have their own proof and reproduction instructions. Sources for the positive Hamiltonian witness compiler are included beside its tests. To recheck the central Lean sources, run `MATHLIB_ROOT=/path/to/mathlib4 sh investigations/check-lean.sh` with the matching Lean executable on PATH and the Mathlib libraries already built.

The files identify which statements have Lean proofs, which have mathematical arguments and which have finite controls. The central Lean modules cover the fixed-junta row and inconsistency certificates, the asymmetric row aggregation, parity-edge count, Boolean selector semantics, and arithmetic identities for matching marginals and extracting the hard polynomial. The separate fleet-locality directory checks the end-to-end 3q+1 theorem against the original project definitions. The official arithmetic bridge directory verifies the transfer with Anthropic’s definitions and the upstream exact and border lower bounds as explicit premises. [Arithmetic bridge and assumptions](official-arithmetic-transfer/README.md)

The full hardness reductions, the randomized locality theorem, and asymptotic query claims have written arguments. The companion directories describe their separate Lean coverage. The material is independent research with no assertion of publication priority or peer review. The public project records linked above carry the swarm's own verification status.
